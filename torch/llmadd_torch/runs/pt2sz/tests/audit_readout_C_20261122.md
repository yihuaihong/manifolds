## (2) 证据撑得住的最强说法；计划句子哪里说过了、哪里说少了
- **重要 I-1（说过了：措辞和机制）**：190M 以上增益变大，全部来自 none 臂下降（27.98 → 25.98 → 24.45），prior 臂基本不动（77.93 / 78.33 / 77.42）。53M → 190M 两臂都涨，prior 涨得更多。在固定 3e8 tokens 下，tpp 从 21.2 降到 0.745，AUDIT.md:181-185 明确禁止写「the prior helps larger models more」。「grows with model size」容易被读成这个意思。另外五个均值并不单调（93M 的 51.6 高于 190M 的 49.9），所以应写「increases with log size（OLS 趋势）」，并把 tpp 混淆放进集中写限定的地方。
- **重要 I-2（漏了必须引用的限定）**：用户已回复「不改」（AUDIT.md:337-339），RUNBOOK_C.md:45-54、:60 要求和判词写在一起的内容句子里一条都没有：①只是部分确认：5 个尺寸里有 3 个在登记前就看过；②在这三个格子已观测的条件下，真实不增长时仍有 16–38% 读成 SHOWN（AUDIT.md:201-203、:208）；③SHOWN 的似然比约 1.7–3.8（tests/audit_build.md:101）；④I1 的选点敏感性。
- **重要 I-3（I1 已经发生在这批数据上）**：把 294M 的 8-seed 增益按 stage A seed 0–3 上换一档的差值平移（假设 seed 4–7 平移同样多，只作描述）：win-ctx 换成 1.2e-3（pt2main rule 1 会选的，AUDIT.md:362）→ b +1.04，(a) 下界 −0.21，NOT SHOWN；win-ctx 换成 3e-4 → b +1.10，NOT SHOWN；none 换成 4.8e-3 → b +1.54，但 (c) 下界 −0.03，NOT SHOWN；93M 换档后仍是 SHOWN。**斜率的符号稳**：所有变体 b 在 +1.04..+1.54 之间，16 种选点组合下 seed 0–3 的斜率都在 +0.89..+1.45。**SHOWN 这个标签不稳**：294M 的选点只要换一档就会翻成 NOT SHOWN。
- **重要 I-4（可能说少了）**：seed 4–7 在所有格子里都没参与选点。只用这一半，b = +1.41，比 8 seed 的 +1.27 还大。所以 winner's curse（F98 I6，AUDIT.md:188）造不出这个斜率，这条限定可以换成这个数。93M seed 0–3 的 55.0 和 seed 4–7 的 48.3 之差来自 none 臂的 seed 噪声（seed 4 / 6 的 none 是 40.1 / 35.1），不是选点造成的：none 臂的 winner's curse 方向相反。
- 次要：①93M 的 seed SD 是 9.1，模拟用的 σ 是 5.48（AUDIT.md:194-195），按实际噪声算的条件假 SHOWN 率更低（build audit 里 SD×1.5 时是 0.24），所以照引 16–38% 偏保守；②「p = 0.08」是残差 t 的双侧 p（单侧 0.039），要标明；③登记的 within-size bootstrap 忽略了跨尺寸的 seed 相关，比 joint CI [+0.32, +2.25] 宽，句子用登记的那个是对的；④去掉 b11 后的斜率 +2.05 是事后分析，不要拿来升级结论。

**证据撑得住的最强说法**（第一句，带适用范围）：「在 2% 算术、固定 300M tokens、同一集群（A100-80GB）上，helix prior 让训练全程平均的 held-out 准确率在 53M / 93M / 190M / 294M / 505M 分别提高 +48.0 / +51.6 / +49.9 / +52.3 / +53.0 点（每个尺寸 8/8 seed），而且增益随 log 尺寸上升：每 e 倍 non-embedding 参数 +1.27 点（53M 到 505M 约 +4.3 点）。预登记检验读数 SHOWN：seed-bootstrap 90% CI [+0.02, +2.49]，两半 seed 都为正，残差 90% 区间 [+0.13, +2.41]，双侧 p = 0.08。」限定集中写成一句：「5 个尺寸中有 3 个在登记前已看过，所以只是部分确认：在已观测格子条件下，真实不增长时仍有 16–38% 读成 SHOWN，SHOWN 的似然比约 1.7–3.8；294M 选点换一档，SHOWN 标签会翻（符号不翻，b 在 +1.04..+1.54）；固定 tokens 时尺寸和 tpp（21 → 0.75）混在一起，190M 以上增益上升是因为 no-prior 基线下降。」

- **最可能测错的地方**：计划句子里 190M（+50.0 → +49.9）和 294M（+52.4 → +52.3）两处二次舍入。读数本身逐项复现，没有算错。
- **可能被测没或写没的真效应**：选点不涉及的那一半 seed（4–7）给出 b = +1.41，可以用来回应 winner's-curse 的限定，计划句子没用上。I-3 的选点平移里也有让 b 变大的方向（294M none 换成 4.8e-3 时 b = +1.54），它也会让 SHOWN 翻成 NOT SHOWN，所以选点敏感性两个方向都有，不只是偏向假阳性。
- **证据撑得住的最强结论**：在固定 300M tokens、同一集群上，每个尺寸增益都约为 +48 到 +53 点（8/8），这一点很稳。随尺寸上升的趋势 +1.27 / e-fold（预登记 SHOWN，(a) 勉强通过，双侧 p = 0.08）站得住，但只是部分确认，SHOWN 标签对 294M 选点敏感，190M 以上的上升来自基线下降。计划句子在数值上没有说弱；它说过头的地方是措辞（「grows with model size」）和漏写的必引限定。
