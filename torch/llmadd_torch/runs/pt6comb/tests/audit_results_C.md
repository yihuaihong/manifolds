## 1. 独立重算（问题 1）

### 1.1 方法

recompute.py 自己从 run JSON 重建每个流形的逐 eval 序列：
- numbers：held_b11..b33 六个桶的均值。
- s4_hard：用 hits_s4_held 在 rb6 s4_hard 的题号上求均值。每 seed 的题数和 chance 与 rb6 的 S4_HARD_PRE 完全相同，例如 seed 8 是 191 题、chance 25.16。
- dim strict：用 hits_dim_held 在 strict_mask 上求均值。
- 比较类：用 hits2_<d>_held 求均值。重建值和日志里的 `<d>_held_2way`、metrics area 都对得上（≤1e-9 / 1e-6）。

在此基础上：
- area = 100 × 75 次 eval 的均值。
- g / h / u 的逐 seed 值。
- 统计：单侧 t 用 scipy；Holm 自己实现；bootstrap 用 10,000 次、default_rng(0)、5/95 百分位；95% t 区间。
- LM 份额：各 run 窗口内 26 次 eval 上 a/(a+b) 的中位数，再在 cell 内取中位数，并分两半。
- 裁剪系数。
- LM 代价：最后一次训练中 eval 的 val loss / bpb。

逐字段对 readout.json 的范围：
- 每个流形的 mean_g / h / u。
- 逐 seed 的 g / h / u 数组。
- p_help、Holm、p_int、wins。
- boot90_g / h / u 和 ci95_g。
- mean6_gain 的均值和 CI。
- lm_same_lr。

结果：**0 处不一致**。官方脚本重跑（readout_rerun.*）与存档逐字节相同。

### 1.3 同 lr LM 代价的 7 倍差异（Provisional look 1 留的问题）

seed 8–15 的均值是 +0.018，seed 0–3 是 +0.0026，差 7 倍。原因是每个 seed 集里各有一个 run 落在偏差的盆地里：
- seed 8–15：s9 的 all6@2e-3 val loss 停在约 4.126，该 seed 的代价是 +0.061。
- seed 0–3：s0 的 none@2e-3 停在约 4.11，该 seed 的代价是 −0.035。

这两个都是整个尾段的持续偏移（最后 5 次 eval 的均值相同），不是最后一次 eval 的偶然跳动。中位数在两个 seed 集里一致：
- seed 8–15：+0.0114。
- seed 0–3：+0.0106。

去掉 s9 后，seed 8–15 的均值约 +0.012。相对量：+0.018 / 4.067 ≈ 0.44%；中位数约 0.27%。

结论：不是算错，均值对单个 run 敏感。写 +0.018 时注明 @2e-3 即可，加上中位数 +0.011 更准确。
